## Objective

Introduce the **"Learn"** stage of Observe → Learn → Suggest → Permission → Automate.

The system can already answer "what happened?" (Sprint 17). Sprint 18 lets it answer **"what patterns exist in what happened?"** through deterministic aggregation only — no intelligence, AI, scoring, prediction, ranking, anomaly detection, or recommendations.

---

## Architecture Decision

**Derived analytics layer over observations.**

```
Observation (derived, read-only)
  ↓
WorkspaceAnalyticsService (aggregate; no mutation, no commands, no permissions)
  ↓
WorkspaceMetrics (pure, deterministic)
  ↓
GetWorkspaceMetrics (governed read) → IPC → future consumers
```

Analytics consumes `ObservationService` output and delegates aggregation to a pure domain type (`WorkspaceMetrics::from_observations`). Given the same observations and timestamp, the output is fully reproducible. The service never touches repositories or the database API directly.

**Rejected:** any AI model, learning engine, or ML system (Observation → AI → Decision). This layer is Observation → Aggregation → Metrics only.

---

## Analytics Domain Model

`WorkspaceMetrics { generated_at, observation_count, lifecycle_activity_count, resource_change_count, layout_change_count, settings_change_count, resource_creation_count, resource_deletion_count, activity_by_category }`

- `CategoryActivity { category, count }` — per-category breakdown in fixed, deterministic order.
- Resource creation/deletion are counted from `ResourceChange` observations whose `source_event_type` ends with `.created` / `.deleted`.
- `validate()` enforces a non-empty timestamp, category counts summing to `observation_count`, and creation+deletion ≤ resource-change count.

---

## Persistence Decision

**No persistence.** Metrics are derived on demand from observations (themselves derived from the audit trail). No metrics table, analytics repository, or migration was added. A durable analytics store is deferred until a real consumer (e.g. long-horizon trend analysis) justifies it.

---

## Governance Decision

**`GovernanceClass::Governed`** for all actors. Metrics reveal workspace activity history (sensitive). Required capability: **`audit.read`** (reused — metrics expose the same underlying activity as observations/audit; no new capability invented). Permission subject: `System`.

---

## Audit Decision

**No new audit event type.** Governed metrics reads are audited by the existing pipeline governed-read path, consistent with `GetObservations` / `GetAuditHistory`. Low-frequency; no audit pollution introduced.

---

## IPC Decision

**Added `get_workspace_metrics`** — additive read endpoint returning `IpcResponse<WorkspaceMetrics>` with an optional `limit`. No database exposure and no internal analytics details beyond the metrics fields.

## Remaining Risks

| Risk | Mitigation |
|------|------------|
| Metrics inherit observation/audit coupling | Accepted; analytics is a projection-of-a-projection. Dedicated store deferred |
| `limit` bounds the analysis window | Documented; default 200, max 500, over-reads audit up to `MAX_AUDIT_SCAN` |
| Scope creep toward scoring/AI | Prohibited by design: aggregation only, pure counts, no ranking/prediction |
