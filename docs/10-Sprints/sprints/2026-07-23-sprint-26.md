## Objective

Create a deterministic context enrichment layer so `WorkspaceContext` can include recent execution outcomes.

Trusted consumers can query: **"What happened after previous executions?"**

This is read-only historical context. It is **not** AI memory, learning, reinforcement, ranking, prediction, automation, or self-improvement.

---

## Architecture Decision

**Option A: Derived execution outcome context**

```
Audit
  ↓
ExecutionOutcomeService
  ↓
ExecutionContextService → ExecutionContextSummary
  ↓
WorkspaceContext (additive field)
  ↓
Future consumers
```

No redesign of governance boundaries. Outcomes remain historical facts; context remains an assembled read model.

---

## Persistence Decision

**None.** No new database, repository, table, or event system. Summary is derived on demand from audit → outcomes → aggregation.

---

## Governance Decision

**No new capability, permission, or command.** This is context derivation inside the existing `WorkspaceContext` assembly path. `GetWorkspaceContext` already governs the composed read (`audit.read`).

---

## Audit Decision

**No new audit event types.** Audit remains the durable source of truth for execution history. Sprint 25 outcome classification continues to project from existing `ExecuteIntentRequest` success/failure events.

---

## IPC Decision

**Deferred.** No consumer exists yet (same unused-surface rule as Sprint 23–25).

## Remaining Risks

| Risk | Mitigation |
|------|------------|
| Cancelled outcomes rare until cancel path exists | Classifier + aggregation ready; empty/cancelled counts validated in unit tests |
| Context payload grows with outcome history | Bounded by existing `limit` passed into context assembly |
| No dedicated IPC for execution context alone | By design — exposed only via composed `WorkspaceContext` |
| Suggestions remain derived separately | Context does not embed suggestion proposals; avoids circular derivation |
