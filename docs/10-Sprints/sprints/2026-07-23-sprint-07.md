## Objective

Create a durable record of important system activity to support future debugging, transparency, user trust, AI observation, permission review, and automation auditing — without AI, memory, automation UI, or feature creep.

---

## Architecture

```
Commands
    ↓
Permission Gate
    ↓
CommandPipeline ──→ AuditService (command.executed / command.failed)
    ↓
Services
    ↓

    ↓

    ↓

    ↓

    ↓
```

## Audit Domain Model

| Field | Purpose |
|-------|---------|
| `id` | `AuditEventId` (typed) |
| `timestamp` | RFC3339 UTC |
| `event_type` | e.g. `command.executed`, `workspace.entity.created` |
| `actor_type` | `system`, `user`, `service` |
| `actor_id` | Optional actor identifier |
| `command_name` | Optional command name for command audits |
| `success` | Whether the action succeeded |
| `metadata` | Generic JSON string (sanitized) |

---

## Privacy Boundaries

Recorded:

- Command names and success/failure
- Public error codes on failure (`error_code` only)
- Domain event names and sanitized metadata (IDs, versions)

**Not recorded:**

- Settings theme values
- Workspace names in domain event metadata
- Secrets, credentials, or full command payloads

## Deadlock Prevention

Domain events are published **after** releasing the database lock in mutation commands. This prevents the audit subscriber (which needs the database lock) from deadlocking with in-flight command transactions.
