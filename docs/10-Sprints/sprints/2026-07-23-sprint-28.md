## Objective

Create a governed **cancellation request** boundary so operators can request that a previously identified execution be cancelled.

This sprint does **not** implement runtime interruption, cancellation tokens, or process termination. It records cancellation authority through the existing command pipeline.

---

## Architecture Decision

**Option A: Cancellation request layer only**

```
Execution identity (execution:{suggestion_id})
  ↓
RequestExecutionCancellation (governed mutation)
  ↓
ExecutionCancellationService (validate vs outcomes)
  ↓
CommandPipeline → Permission → Audit
  ↓
ExecutionOutcome(cancelled)  ← classifier extension
```

Reuse existing execution identifiers. No parallel identity system.

**Semantics**

| Case | Behavior |
|------|----------|
| Unknown execution | Reject (`UnknownExecutionRequest`) |
| Completed execution | Reject explicitly (`CannotCancelCompletedExecution`) |
| Failed (known, not completed) | Accept → `CancellationStatus::Requested` |
| Already cancelled | Reject |

---

## Persistence Decision

**None.** No cancellation table or repository. Durable record is the existing command audit trail.

---

## Governance Decision

**No new capability.** Reuses `audit.write` (same boundary as `ExecuteIntentRequest`). Guard/permission/policy remain in the pipeline; the service does not mutate or bypass them.

---

## Audit Decision

**No new event types.** Success metadata on `RequestExecutionCancellation`:

```json
{
  "execution_request_id": "execution:…",
  "cancellation_status": "requested",
  "cancellation_id": "cancellation:…",
  "reason": "sanitized"
}
```

`classify_execution_outcome_event` additively recognizes successful cancellation audits as `Cancelled`.

---

## IPC Decision

**Deferred.** No consumer.

## Remaining Risks

| Risk | Mitigation |
|------|------------|
| Sync execution means "in-flight" cancel is not yet meaningful | Documented — request layer only; runtime stop is future |
| Completed executions cannot be cancelled | Explicit error by design |
| Cancelled + Failed both appear in outcome history | Deterministic facts; consumers must not over-interpret |
| No IPC surface | Follow unused-surface rule |
