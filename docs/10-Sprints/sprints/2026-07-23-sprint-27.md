## Objective

Implement duplicate execution protection so the system can answer:

**"Has this execution request already been executed?"**

Deterministic idempotency for `ExecuteIntentRequest` — without an execution store, workflow engine, or retry system.

---

## Architecture Decision

**Option A: Audit-derived execution guard**

```
ExecuteIntentRequest
  ↓
(Permission / Policy — existing pipeline)
  ↓
ExecutionGuardService  ← reads ExecutionOutcomeService ← Audit
  ↓
Allow / Reject (DuplicateExecution)
  ↓
CommandPipeline dispatch → Command → Audit
```

Reuses existing canonical id: `execution:{suggestion_id}` (Sprint 24–26).

**Block rule:** only prior **Completed** outcomes block. Failed/cancelled history remains retryable (no permanent lock on failure).

---

## Persistence Decision

**None.** No idempotency table, repository, or execution database. Guard derives from existing audit → outcome projection.

---

## Governance Decision

**No new capability or permission.** Guard runs inside `ExecuteIntentRequest::execute` after the pipeline has already enforced authority. It protects authority; it does not grant it.

---

## Audit Decision

**No new event types.** Duplicates rejected via the existing command failure audit path (`command.failed` + merged `error_code: duplicate_execution` + execution request failure metadata).

---

## IPC Decision

**Deferred.** No consumer surface required.

## Remaining Risks

| Risk | Mitigation |
|------|------------|
| Outcome scan window miss for very old completions | Bounded scan (200 outcomes); acceptable for Phase 1; widen later if needed |
| Failed attempts still leave audit noise | By design — failure path records rejection without new event types |
| Concurrent double-dispatch race | Single-process desktop; no distributed lock; document as Phase 1 limit |
| Retries after failure re-dispatch mapped command | Intentional — architecture does not define permanent failure locks |
