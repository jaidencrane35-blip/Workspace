# Sprint 71 — Governed Automation Contract Foundation

| Field | Value |
|-------|-------|
| **Date** | 2026-07-24 |
| **Batch** | Phase 4 Batch 6 |
| **Theme** | Durable user-approved future intent — no autonomous execution |

## Outcome

Automation Contracts exist as first-class, workspace/project-scoped domain objects with separate status and approval_state. Triggers and intent are definitions only. Workspace Intelligence can read contracts but cannot mutate them. Future execution still requires Command Pipeline → Permission Gateway.

See [Governed Automation Contracts](../../05-AI/GOVERNED-AUTOMATION-CONTRACTS.md).

## CASE coverage

1. Persist across restart  
2. Workspace/project ownership  
3. Cannot execute commands  
4. Cannot bypass Permission Gateway  
5. Approval ≠ execution permission (no grants)  
6. Revoked not active  
7. Intelligence can read  
8. Intelligence cannot modify  
9. Assistant cannot authorize  
10. Prepare intent still governed by pipeline  

## Explicit non-goals

No background automation, schedulers, agents, or automation-specific authority.
