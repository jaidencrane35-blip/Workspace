## Objective

Create the governed execution boundary between an approved [`SuggestionIntentRequest`](../../packages/domain/src/suggestion_intent/mod.rs) and existing [`CommandPipeline`](../../packages/kernel/src/commands/pipeline.rs) execution — without automation, AI, or bypass paths.

Approval grants permission to **request** execution. It does not grant permission to bypass governance.

---

## Architecture Decision

**Option A: Explicit execution request**

```
SuggestionIntentRequest (audit-backed bridge)
    ↓
ExecuteIntentRequest (governed mutation)
    ↓
GovernedIntentExecutionService::prepare
    ↓
IntentExecutionService::validate_request (action intent)
    ↓
CommandPipeline::execute_*_with_action
    ↓
Existing mapped command (CreateZone / GetAuditHistory / GetLayoutSnapshot)
    ↓
Audit
```

This is **not** automation. Each step requires explicit governed command invocation.

---

## Persistence Decision

**None.** No execution database, suggestion store, or workflow tables. Execution requests and outcomes are recorded through existing audit metadata on `ExecuteIntentRequest`. Bridge and approval history remain in prior audit events.

---

## Governance Decision

`ExecuteIntentRequest` is a **governed mutation** through `CommandPipeline` with **`audit.write`** and **`PermissionSubject::System`**. Inner mapped commands run via `execute_mutation_with_action` / `execute_query_with_action` — full permission and audit for each command. No service bypasses the pipeline.

---

## Audit Decision

`ExecuteIntentRequest` records:

```json
{
  "execution_request": true,
  "suggestion_id": "...",
  "intent_id": "create-zone",
  "execution_status": "executed"
}
```

Inner commands receive their standard audit records. Audit remains authoritative history.

---

## IPC Decision

**Deferred.** No current UI consumer. `CommandHandler::execute_intent_request` is available for future additive IPC.

## Remaining Risks

| Risk | Mitigation |
|------|------------|
| Mapped command dispatch is explicit match table | Extend only when new suggestion→intent bindings are added |
| `GetLayoutSnapshot` requires existing layout | Execution fails closed if layout missing |
| Bounded audit scan for bridge/approval lookup | Same pattern as Sprints 21–23 |
| Future automation remains separate | No scheduler, workers, or autonomous agents introduced |

---

## Explicit Confirmations

- **No persistence added** — audit-only governance records
- **No AI introduced**
- **No automation introduced** — explicit command per execution request
- **CommandPipeline remains authoritative** — all mutations/queries via pipeline with action intent validation
- **Approval ≠ execution authority** — Accept + bridge + ExecuteIntentRequest are separate governed steps
