## Architecture Change

```
Before:  Workspace → Repositories → Graph (implicit / absent)

After:   Workspace → Resource Services → Repositories → Graph (passive)
                              ↓
                         GraphService (node/edge registration)
```

Cross-resource validation (workspace existence) occurs in **commands**, not services. Services own only their resource persistence and graph registration via `GraphService`.

## Deliverables

### Domain (`packages/domain`)

- `graph` module — `GraphRelationship`, `GraphEdge`
- Expanded `DomainError` — resource not found, duplicate, invalid parent
- Shared `validate_resource_name`
- Capabilities — `zone.*`, `application.*`, `widget.*`
- Audit — `resource_ref` field on `AuditEvent`

### Database (`packages/database`)

- Migration `006_graph.sql` — `graph_nodes`, `graph_edges`, audit `resource_ref` column
- `GraphRepository`, `ApplicationRepository`, `WidgetRepository`
- Expanded `ZoneRepository`, `WorkspaceRepository`

### Kernel (`packages/kernel`)

- `GraphService` — passive node/edge registration, lookup, validation
- `WorkspaceService`, `ZoneService`, `ApplicationService`, `WidgetService`
- Commands — Create/Delete/Get for zone, application, widget
- Events — `resource.created/updated/deleted`, `zone.created`, `application.created`, `widget.created`
- Audit pipeline — `ResourceRef` on mutation audit records

### IPC (`app/src-tauri`)

- `create_zone`, `delete_zone`, `get_zone`
- `create_application`, `delete_application`, `get_application`
- `create_widget`, `delete_widget`, `get_widget`
