## Purpose

Establish **who** is performing actions across commands, permission checks, audit records, and domain events — without authentication, accounts, or login.

This sprint introduces **identity only**, not authorization policy changes.

---

## Architecture

```
ActorContext (LocalUser | System)
    ↓
CommandContext
    ↓
CommandPipeline
    ├─ PermissionRequest { actor, command, subject }
    └─ AuditService (actor attribution)
    ↓
DomainEvent (optional actor on mutation events)
    ↓
AuditEventSubscriber
```

### Execution identity model

| Actor | Used when |
|-------|-----------|
| `LocalUser` | IPC-originated commands (`local-user` id) |
| `System` | Kernel init, shutdown, bootstrap lifecycle |
| `AIAssistant`, `Automation`, `Plugin`, `RemoteSession` | Scaffolded only — not active |

### Actor lifecycle

1. **IPC request** → `ipc_actor_context()` returns `LocalUser`
2. **CommandHandler** receives explicit `ActorContext`
3. **CommandPipeline** builds `PermissionRequest` with actor
4. **AuditService** records actor id + type from context
5. **Domain events** from mutations carry `Option<ActorContext>`

---

## Domain model (`packages/domain/src/actor/`)

- `ActorId` — typed identifier
- `ActorType` — classification enum
- `ActorMetadata` — optional non-sensitive label
- `Actor` — immutable identity
- `ActorContext` — execution wrapper passed through commands

---

## Relationships

| System | Integration |
|--------|-------------|
| **Permission** | `PermissionRequest.actor` populated; gate logic unchanged (`AllowAll`) |
| **Audit** | No more hardcoded `System`; reads actor from context/events |
| **Future AI** | `Actor::ai_assistant()` placeholder ready for advisory actions |
| **Future automation** | `Actor::automation()` placeholder for delegated runs |

---

## IPC

`app/src-tauri/src/actor.rs` — internal `ipc_actor_context()` attaches `LocalUser` to all frontend commands. No actor selection UI.

---

## Explicit exclusions

No authentication, login, accounts, profiles, sessions, networking, cloud identities, AI, automation, UI changes.

## Remaining risks

| Risk | Notes |
|------|-------|
| Single local user | `LOCAL_USER_ACTOR_ID` constant until multi-profile support |
| Bootstrap events pre-subscriber | Lifecycle start events may not appear in audit until subscriber timing is addressed |
| Query commands require Ready | Audit query fails after shutdown — by design |
