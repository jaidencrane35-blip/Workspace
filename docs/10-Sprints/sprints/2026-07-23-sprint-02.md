## Objective

Convert the Sprint 01 scaffold into a stronger application foundation by establishing Workspace Core ownership boundaries, configuration persistence, database lifecycle management, and standardized IPC — without building product features.

---

## Scope

### In scope

- Expand `packages/kernel` with state, config, services, and error modules
- `WorkspaceState` owned by Rust (version, runtime status, initialization)
- SQLite-backed configuration (`theme`, `first_run`, `settings_version`)
- `DatabaseService` initialization and bundled migration execution
- Settings table migration (`001_settings.sql`)
- IPC commands: `get_workspace_status`, `get_settings`, `update_settings`
- IPC flow: React → Tauri → Kernel → Database
- Safe command error mapping (no raw internal errors)
- Tests for kernel state, settings persistence, and command mapping
- Frontend displays kernel-owned runtime and settings data

### Exclusions

- AI subsystem, memory, confidence logic
- Automation engine
- Plugin runtime
- Spatial canvas and workspace layouts
- Windows API integration and overlays
- Background services and autonomous behaviour
- Settings UI screens
- User profiles and permission tables

---

## Architecture

```
Tauri Shell (app/src-tauri/commands)
    |
React UI (display only)
    |
WorkspaceKernel (packages/kernel)
    |-- state/     WorkspaceState
    |-- config/    ConfigManager → settings
    |-- services/  ServiceRegistry (placeholder)
    |
workspace-database
    |-- DatabaseService
    |-- SettingsRepository
    |-- migrations/001_settings.sql
```

## Acceptance Criteria

| Criterion | Status |
|-----------|--------|
| Kernel owns runtime state | Required |
| React does not own application state | Required |
| Settings persist through SQLite | Required |
| Database initializes correctly on startup | Required |
| IPC follows React → Tauri → Kernel → Database | Required |
| Tests pass | Required |
| Existing CI remains passing | Required |
| No excluded features added | Required |

---

## IPC Commands (Sprint 02)

| Command | Path | Description |
|---------|------|-------------|
| `get_workspace_status` | Kernel state | Runtime version, status, initialization |
| `get_settings` | Kernel → Database | Read persisted settings |
| `update_settings` | Kernel → Database | Update allowed settings fields |

Errors return `{ code, message }` without internal Rust details.
