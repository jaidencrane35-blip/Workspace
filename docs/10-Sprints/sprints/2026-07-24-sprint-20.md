## Objective

Introduce the deterministic **Suggest** stage of Observe → Learn → Suggest → Permission → Automate.

A `Suggestion` is a deterministic **proposal object derived on demand from `WorkspaceContext`** — never an action. It does not execute, mutate workspace state, grant permissions, or bypass governance. This sprint delivers the read-only proposal layer only. There is no AI, LLM, ML ranking, probability, behaviour prediction, automation rule, or persistence.

---

## Architecture Decision

**Deterministic proposal layer derived from context.**

```
WorkspaceContext (Sprint 19)
        │
        ▼
derive_suggestions(context)   ← pure, threshold-based rules (no AI)
        │
        ▼
SuggestionService::list  →  GetSuggestions (governed)  →  IPC  →  future consumers
```

Suggestions are generated by a pure domain function `derive_suggestions(&WorkspaceContext) -> Vec<Suggestion>`. Rules are simple, deterministic thresholds over the metrics already present in the context (e.g. `resource_creation_count >= 3`). Given the same context, the output is byte-for-byte identical. `ResourceRef` remains the canonical identity and is preserved on any suggestion that references a resource. Commands remain the only mutation mechanism; a suggestion carries no authority.

### Preserved future flow (documented, NOT built)

```
Context → Suggestion → (future) User Approval → Intent → Capability → Permission → CommandPipeline → Execution
```

A suggestion is the *input* to a future, explicit user-approval step. Acceptance must route through the existing intent/command governance path — it is intentionally out of scope this sprint.

## Suggestion Domain Model

`Suggestion { id, suggestion_type, title, description, source_context, related_resource_ref, confidence, status }`

- `suggestion_type: SuggestionType` — `WorkspaceActivity | ResourceGrowth | LayoutActivity` (small, deterministic set grounded in what the context contains).
- `status: SuggestionStatus` — `Pending | Accepted | Rejected | Expired`. Generation always yields `Pending`.
- `source_context: String` — short deterministic label of the context input that produced it (e.g. `"metrics.resource_creation_count"`), not the whole context.
- `related_resource_ref: Option<ResourceRef>` — canonical identity of the referenced resource (the workspace) when applicable.
- `confidence: SuggestionConfidence { supporting_observation_count, basis }` — **deterministic metadata only**: a supporting count and a human-readable rule basis. Not a probabilistic or learned score.
- `validate()` enforces non-empty `id`, `title`, `description`, and `source_context`.

Deterministic generation rules (threshold-based, non-AI):

| Rule | Condition | Type |
|------|-----------|------|
| Resource growth | `metrics.resource_creation_count >= 3` | `ResourceGrowth` |
| Layout activity | `metrics.layout_change_count >= 2` | `LayoutActivity` |
| Workspace activity | `metrics.observation_count >= 5` | `WorkspaceActivity` |

---

## Persistence Decision

**None.** No suggestion table, workflow database, memory store, cache, embeddings, or vector database. Suggestions are derived on demand from `WorkspaceContext` (itself derived from authoritative state and the audit trail), exactly like the prior derived layers.

---

## Governance Decision

**`GovernanceClass::Governed`** for all actors (DEC-017). Suggestions derive from the workspace context, which aggregates sensitive activity history and capability information. Required capability: **`audit.read`** — reusing the most sensitive input's capability rather than inventing a new suggestion permission. Permission subject: `System`.

---

## Audit Decision

**No new audit event type.** Governed suggestion reads follow the existing pipeline governed-read path, consistent with `GetObservations` / `GetWorkspaceMetrics` / `GetWorkspaceContext`. Deriving suggestions writes nothing to the durable record (verified by a no-mutation test).

---

## IPC Decision

**Added `get_suggestions`** — additive read endpoint taking `workspace_id` + optional `limit`, returning `IpcResponse<Vec<Suggestion>>`. Mirrors `get_workspace_context` exactly; exposes only the composed read model.

---

## Deferred Items

- **`AcceptSuggestion` / `RejectSuggestion` are intentionally NOT implemented.** Acceptance is an action and must route through the existing intent → capability → permission → command pipeline. Building it now would risk letting a proposal bypass governance. It is deferred to a future sprint alongside the user-approval stage.

## Deliverables

### Domain
- `SuggestionType`, `SuggestionStatus`, `SuggestionConfidence`, `Suggestion`, `SuggestionError`, `Suggestion::validate`

### Kernel
- `SuggestionService::list` — builds context via `WorkspaceContextService`, then applies the pure generator
- `GetSuggestions` read command (Governed, `audit.read`, System; default limit 200, max 500)
- `CommandHandler::get_suggestions`
- `KernelError::SuggestionValidation`

### IPC
- `get_suggestions`

## Remaining Risks

| Risk | Mitigation |
|------|------------|
| Threshold rules are coarse | Accepted; deterministic and simple by design; can be refined without introducing inference |
| Metrics are workspace-instance-global, not per-workspace | Inherited from Sprint 17–19 derived layers; unchanged this sprint |
| Scope creep toward AI ranking / auto-execution | Prohibited by design: pure threshold rules, proposals only, no acceptance path |
| Pressure to persist accepted/rejected state | Deferred acceptance must route through commands/audit, not a new suggestion store |
