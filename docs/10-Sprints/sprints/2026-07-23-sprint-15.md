## Objective

Formalize workspace actions as explicit metadata before automation, AI, or plugins exist.

---

## Architecture Decision

**Metadata-first (Option A):**

```
Actor
  ↓
ActionIntentRequest (what)
  ↓
IntentExecutionService (validate)
  ↓
Command (unchanged)
  ↓
CommandPipeline
  ↓
Audit
```

Motivation intent (`IntentContext` — why) remains separate from action intent (`ActionIntentRequest` — what).

No planner, command graph, or execution engine was added.

---

## Persistence Decision

**No new persistence.**

Existing `AuditEvent` records executed commands. Action intent metadata is validated in-memory before pipeline execution; intent creation is not audited separately.

---

## IPC Decision

**No intent IPC endpoints.**

No UI or external consumer requires intent creation or execution over IPC yet. Existing command IPC paths remain unchanged.

---

## Governance Decision

Action intents declare `capability_required`. `IntentExecutionService::validate_before_command` ensures:

1. Intent exists in registry
2. Request metadata/target rules pass validation
3. Intent maps to the command being executed
4. Intent capability matches `command.required_capability()`

Commands still run exclusively through `CommandPipeline`. Intent cannot bypass policy or permission gates.

---

## Audit Decision

**No audit event for intent validation.**

Audit continues to record command execution outcomes only. Intent validation failures return errors before pipeline audit recording.

---

## Deliverables

### Domain
- `ActionIntentDefinition`, `ActionIntentRequest`, `ActionIntentRegistry`
- `ActionIntentCategory`, `TargetRequirement`, `ActionIntentMetadata`
- Static registry of 20 supported command mappings

### Kernel
- `CommandIntentMapping` — intent id → command name
- `IntentExecutionService` — validation + capability matching
- `CommandPipeline::execute_mutation_with_action`
- `CommandPipeline::execute_query_with_action`

### Tests
- Domain validation and registry uniqueness
- Mapping resolution and capability checks
- Pipeline integration with action intents
- Regression: existing tests unchanged

| Risk | Mitigation |
|------|------------|

| Registry drift from commands | Integration tests verify command/capability mappings |

| Capability set still not enforced | Intent validates declared capability; gate enforcement is a future sprint |
