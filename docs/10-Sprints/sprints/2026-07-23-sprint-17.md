## Objective

Expose a neutral, read-only answer to: **"What is happening over time?"**

Observations are a consumer-friendly interpretation layer over recorded activity. They are a prerequisite for later Observe → Learn → Suggest work (AI assistance, automation, suggestions) but introduce none of it.

---

## Architecture Decision

**Option A — Derived observation layer, projected over the audit trail.**

```
Domain Events (authoritative, ephemeral)
  ↓ (already) AuditEventSubscriber → AuditService → SQLite audit trail (durable history)
  ↓
ObservationService (derive on read, orchestration only)
  ↓
Observation records (derived, disposable, neutral)
  ↓
GetObservations (governed read) → IPC → future consumers
```

Domain events remain the source of truth. The audit trail is already the only durable record of what happened, so observations are derived from it on read — exactly the way Sprint 14 projects a `WorkspaceSnapshot` over authoritative domain state.

A domain classifier (`classify_event`) maps recorded event types to a category + importance and returns `None` for governance bookkeeping (`command.executed` / `command.failed`) and unknown types. The observation stream therefore reflects workspace activity, not command/read accounting, and deliberately hides audit internals (command names, capability strings, success flags).

**Rejected alternative:** an in-memory collector + ring buffer subscribed to the event bus. It would add new mutable kernel state, an eviction policy, and a second bus consumer — premature infrastructure with no current consumer (rules 13–15).

---

## Persistence Decision

**No persistence.** Observations are derived on demand from `AuditService::list_recent`. The audit trail is already the durable history; a second store would duplicate it and is premature infrastructure. Future AI memory / analytics can justify a dedicated observation store when a real consumer exists.

---

## Governance Decision

**`GovernanceClass::Governed`** for all actors. Observations reveal activity history and user behavior (sensitive). Required capability: **`audit.read`** (reused — observations expose the same underlying information as audit; no new capability was invented). Permission subject: `System`.

---

## Audit Decision

**No new audit event type.** Governed observation reads are audited by the existing pipeline governed-read path, consistent with `GetAuditHistory`. This is acceptable and low-frequency. If a high-rate consumer (e.g. a poller) emerges later, a telemetry-separate path should be considered — but not now.

---

## IPC Decision

**Added `get_observations`** — additive read endpoint returning `IpcResponse<Vec<Observation>>` with an optional `limit`. Consistent with Sprints 14 and 16 exposing the stable read surface even without a UI consumer. No internals are exposed.

---

## Domain Model

`Observation { id, occurred_at, category, importance, source_event_type, summary, actor_type, actor_id, resource_ref, metadata }`

- `ObservationCategory`: `Lifecycle | ResourceChange | LayoutChange | SettingsChange`
- `ObservationImportance`: `Low | Normal | High`
- `classify_event(event_type) -> Option<(category, importance)>` (pure; `None` filters bookkeeping/unknown)
- `neutral_summary(category, event_type) -> String` (pure, deterministic, non-sensitive)

---

## Deliverables

### Domain
- `Observation`, `ObservationCategory`, `ObservationImportance`, `ObservationError`, `validate`
- `classify_event`, `neutral_summary` (pure)

### Kernel
- `ObservationService::list_recent` — derives observations from the audit trail (orchestration only; reads `AuditService`)
- `GetObservations` read command (Governed, `audit.read`, System)
- `CommandHandler::get_observations`
- `KernelError::ObservationValidation`

### IPC
- `get_observations`

## Remaining Risks

| Risk | Mitigation |
|------|------------|
| Observation coupled to audit schema/retention | Accepted trade-off; documented. Dedicated observation store deferred until a real consumer (AI memory) exists |
| Perceived duplication of `GetAuditHistory` | Distinct neutral shape (category/importance/summary); hides governance internals; filters command bookkeeping |
| `limit` under-fill after filtering | Bounded audit scan window (`MAX_AUDIT_SCAN`), map, then truncate to `limit` |
| Governed-read UX/audit cost | Low-frequency; audited like audit history. Telemetry-separate path considered only if a high-rate consumer appears |
