## Objective

Create a deterministic **current-state interpretation** for a single `execution_request_id`.

Answer: **"What is the current interpreted state of execution:X?"** using existing audit-derived outcome facts — without automation, mutation, or a new store.

---

## Architecture Decision

**Option A: Audit-derived execution reconciliation**

```
Audit Trail
  ↓
ExecutionOutcomeService
  ↓
ExecutionReconciliationService
  ↓
ExecutionReconciliation (state + dispatch/cancel flags)
  ↓
GetExecutionState (governed read, audit.read)
```

No redesign of execution, guard, or cancellation mutation paths.

### Precedence

| Condition | State | dispatch_allowed | cancellation_allowed |
|-----------|-------|------------------|----------------------|
| No outcomes | Unknown | false | false |
| Any Completed | Completed | false | false |
| Else any Cancelled | Cancelled | true | false |
| Else any Failed | Failed | true | true |

**Cancelled** is an outcome fact. Per Sprint 27 it does **not** block retry.

---

## Persistence Decision

**None.** No tables, migrations, repositories, or caches.

---

## Governance Decision

`GetExecutionState` is **Governed** with **`audit.read`** and **`PermissionSubject::System`** — same pattern as `GetExecutionOutcomes`. No new capability.

---

## Audit Decision

**No new events or metadata.** Audit remains source of truth; reconciliation only interprets existing outcome projections.

---

## IPC Decision

**Deferred.** CommandHandler exposes `get_execution_state` for future IPC; no Tauri surface yet.
