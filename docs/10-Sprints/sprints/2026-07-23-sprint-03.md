## Objective

Harden the runtime architecture before user-facing features: lifecycle management, service ownership, standardized IPC contracts, structured logging, and health reporting.

---

## Scope

### In scope

- Unified lifecycle model (`Starting`, `Initializing`, `Ready`, `Error`, `ShuttingDown`)
- Kernel-owned initialization sequence and service startup order
- Named service registry (`database`, `configuration`) with health tracking
- `get_workspace_health()` IPC command
- Standard IPC envelope: `{ success, data?, error? }`
- Structured logging (`log` + `env_logger` in application shell)
- Database initialization failure handling and migration error context
- Tests for lifecycle, migration failures, and IPC response format
- Frontend displays health via standardized IPC

### Exclusions

- AI, automation, plugins, spatial canvas, layouts, overlays
- Windows APIs, background agents, user workflows
- Telemetry, cloud logging, analytics

---

## Architecture Changes

```
React UI (display only, IpcResponse client)
    ↓
Tauri Commands (standardized envelope)
    ↓
WorkspaceKernel
    ├── lifecycle/     LifecycleState transitions
    ├── health/        WorkspaceHealth
    ├── services/      database + configuration registry
    └── state/         WorkspaceState
    ↓
workspace-database (DatabaseService lifecycle)
```

### IPC envelope

Success:
```json
{ "success": true, "data": { } }
```

Failure:
```json
{ "success": false, "error": { "code": "...", "message": "..." } }
```
