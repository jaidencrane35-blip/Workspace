## Objective

Add lifecycle **visibility** for suggestions without persistence or automation.

After Sprint 21, Accept/Reject decisions are recorded in the audit trail, but the system could not represent suggestion lifecycle state beyond creation (derived proposals) and one-shot decisions. Sprint 22 introduces an audit-derived lifecycle projection — the same pattern as Observation and Analytics.

This sprint is **not** automation.

---

## Architecture Decision

**Option A: Audit-derived lifecycle projection**

```
Audit Trail
    ↓
SuggestionLifecycleService (orchestration only)
    ↓
classify_suggestion_lifecycle_event (pure domain)
    ↓
SuggestionLifecycleRecord
    ↓
GetSuggestionLifecycle (governed read) → IPC
```

No suggestion database table, repository, workflow engine, or execution queue.

---

## Persistence Decision

**None.** Lifecycle records are derived on demand from existing audit history, exactly like Observations. Durable memory of decisions remains the audit trail (`command.executed` + metadata from Accept/Reject).

---

## Governance Decision

**`GovernanceClass::Governed`** for all actors (DEC-017). Lifecycle derives from sensitive governance history. Required capability: **`audit.read`**. Permission subject: **`System`**.

---

## Audit Decision

**No new audit event types.** Lifecycle reads follow the existing governed-read pipeline. Classification recognizes:

- `AcceptSuggestion` → `accepted`
- `RejectSuggestion` → `rejected`
- Explicit `metadata.lifecycle` / `metadata.decision` when present
- `GetSuggestions` → `presented` only when metadata includes `suggestion_id` (per-record)

Command bookkeeping and unrelated workspace events are ignored.

---

## IPC Decision

**Added `get_suggestion_lifecycle`** — additive read endpoint with optional `limit`, returning `IpcResponse<Vec<SuggestionLifecycleRecord>>`. Mirrors `get_observations`.

## Remaining Risks

| Risk | Mitigation |
|------|------------|
| `created` / `presented` / `expired` lack dedicated audit signals today | Domain enum + classifier support explicit `metadata.lifecycle`; records emitted only when audit carries `suggestion_id` |
| Per-suggestion `presented` requires metadata on governed reads | Deferred until explicit presentation audit metadata is added without persistence |
| Lifecycle scan window is bounded | Same bounded audit scan pattern as ObservationService |
