## Gap analysis (why concepts feel different)

| Dimension | Concept boards | Current shipped UI | Gap |
|---|---|---|---|
| Visual hierarchy | Card grid / spatial hub; brand and work first | Flat text column; kicker + headline + form | Work is not the hero |
| Emotional response | Calm place; “my desktop environment” | Utility / research kit | Feels like tooling |
| Cognitive load | Glanceable cards; details secondary | Dense instructional prose and scopes | Too much process text |
| Information density | Visual app cards; metadata in utilities | Process IDs, scopes, monitors primary | Engineering-first |
| Discoverability | Dock / hub actions obvious | Phase tabs Save/Resume/Pilot/Help | Implementation phases as nav |
| Interaction flow | Arrive → see work → continue | Arrive → create workspace lecture | Friction before value |
| Premium feel | Depth, glass, scenic focus, intentional spacing | System-ui forms, white textareas, empty black | Commodity web form |
| Desktop-first | Window previews, docks, spatial layout | Left-aligned documentation pane | Not desktop-native |
| Interruption recovery | Return to a place / continue work | “Nowhere to keep this yet” / research forms | Wrong job story |

Root cause: Experience presents Product Proof *machinery* (scopes, consents,
phases) as the primary product. Blueprint requires the engine to serve the
companion experience — not become it.

---

## Convergence target (without capability growth)

1. Launch communicates “this is my workspace.”
2. Navigation is product-oriented: Home, Save, Continue, Check-in, Guide.
3. Empty states invite beginning work; no “Nowhere to keep this yet.”
4. Handoff and recent work precede window/process metadata (inspection remains).
5. Pilot and Help keep truthful content; presentation becomes premium cards.
6. Active workspace persistence defect fixed (pilot blocker).

Trust, contracts, Save/Resume behaviour, and zero ambient observation unchanged.
